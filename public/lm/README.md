## Как собрано по системе

- Цвета: чёрный/белый/серый; `#0095D4` только на главной кнопке шага и на точке «online» у фахівця. Синих ссылок,
  иконок, фонов и оттенков нет; ошибки полей — чёрный текст 600 и чёрная рамка.
- Шрифты: Manrope (заголовки, числа, имена), Onest (всё остальное) с Google Fonts; шкала — из `DESIGN-SYSTEM.md` §3:
  заголовок шага 26/32 px, подсказка 15–17, подпись 13, лейблы 12 капсом.
- Форма: кнопки-пилюли (главная 60 px, 20/700; «Назад» и второе действие — outline), карточки-варианты и карточки 24 px,
  мягкие поля 14 px, плитки категорий 14 px, кадр телефона и панель сцены входа — острые углы (`--radius-image: 0`).
- Рамки 1 px `gray-300`, теней нет (кроме плавающей подписи на карте — как у парящих чипов системы), градиентов нет.
- Заголовки-утверждения заканчиваются точкой, вопросы — знаком вопроса; восклицательных знаков и эмодзи нет.
- Финальный экран каждого квиза — чёрная полоса, как CTA-band системы: белый текст, `gray-400` вторичный, главная кнопка акцентная.
- Логотип — `design-system/assets/logo/logo-on-light.svg`, на чёрном финале — `logo-on-dark.svg`; не перекрашивается.
- Шапка — только логотип и счётчик шага: крестика «выйти» и разделительной линии под шапкой нет (решение владельца 23.09);
  в динамическом квизе экран возражений остаётся доступным по ответу «Ні».
- Телефон на S0 — не HTML-имитация, а скриншот экрана вопроса из демо реального интерфейса в CSS-рамке устройства
  (`.funnel__device--real`, размер через `--dw`, пропорция 9:19.5). На uk-странице тексты экрана украинские и флаг UA,
  на en — оригинал демо. Пересъёмка: `node tools/capture-app-screen.mjs && python3 tools/finish-app-images.py`.
- S1 «3 500+»: под числом два бегущих ряда фахівців (по 14 фото, ряд удвоен для бесшовного цикла, 36 и 42 с в разные
  стороны, наклон −3°, маска-затухание по краям). Плитки 64 px со скруглением 14 px — решение владельца 23.09 вопреки
  правилу системы «фото без скругления». На плитке — маленькая капсула с рейтингом «N/100» и золотой звездой:
  `--color-star: #f5b301` — единственный цвет вне палитры системы, по прямой просьбе владельца. Третьей карточки
  («Найкращі збіги…») на слайде больше нет. `prefers-reduced-motion` останавливает ряды.
- Выпадающий список населённых пунктов: подсветка строки скруглена внутри контейнера (`padding: 6px`, `overflow: hidden`),
  подсказка под полем прячется, пока список открыт; у текстовых полей одна чёрная рамка фокуса вместо рамки + outline.

## Локали и страны

- Язык-оригинал разметки — украинский (`src/*.body.html`). Другие языки собираются словарём `i18n/<код>.json`:
  ключ — украинская строка, значение — перевод. `python3 build.py` собирает `quiz.html`, `quiz-dynamic.html` (uk) и
  `en/quiz.html`, `en/quiz-dynamic.html`; непереведённое попадает в `i18n/_missing-<код>.json`.
- Что зависит от страны, а не от языка, задано в `LOCALES` (`build.py`) и уходит в страницу как `window.QUIZ_LOCALE`:
  телефонный код и маска (`+380 XX XXX XX XX` / `+1 XXX XXX XXXX`), валюта и формат суммы (`2 000 ₴` / `$150`),
  правило множественного числа, список городов с числом фахівців, цены планов Membership, база для примера экономии.
- Заготовки `i18n/pl.json` и `i18n/ru.json` содержат все ключи с пустыми значениями: заполните, добавьте локаль в
  `LOCALES` — и страницы соберутся в `pl/`, `ru/`. Категории права, кейсы и фахівці для страны берутся из базы её сайта.
- В `<head>` каждой страницы — `lang`, `canonical` и `hreflang` для всех локалей.
- Скриншот экрана приложения — свой для каждой локали: `assets/app/question-<код>.jpg|webp`, `build.py` подставляет имя
  по коду локали. Для новой локали снимите экран через `tools/` (словарь подмены текстов — в `capture-app-screen.mjs`).

## Адаптивность

- Кегли плывут по ширине экрана (`clamp`): заголовок шага 22–32 px, подсказки 14–17, варианты 15–17, подписи 12–13.
- Три яруса по высоте: ниже 700 px прячется второстепенное (`funnel__hide-short`), до 900 px — самое тяжёлое
  (`funnel__hide-mid`), выше показывается всё. Ниже 600 px по высоте и уже 360 px по ширине — плотная сетка и кнопки 52 px.
- Экран входа: на коротких экранах телефон в сцене обрезан («выглядывает»), от 760 px по высоте сцена растёт и телефон
  виден целиком (375×812 — 168 px, 430×932 — 203 px); от 900 px ширины первый экран двухколоночный: текст и кнопка слева,
  сцена с телефоном справа на всю высоту (1280×800 — 219 px, 1440×900 — 263 px). Уже 360 px — подпись кнопки «Почати аналіз».
- S1: от 700 px по высоте — два ряда по 64 px, ниже — два ряда по 52 px, ниже 600 px — один ряд 44 px с наклоном −2°.
- Правило файла: базовые правила компонента стоят выше медиа-блоков, иначе медиа перебивается (дважды ловили на `.funnel__stage`
  и `.funnel__device--real`). Дети `.funnel__screen` не сжимаются (`flex-shrink: 0`) — переполнение видно, а не обрезается.

## Проверка

- 360×640, 375×667, 375×812, 414×896: каждый экран без прокрутки (кроме состояний с показанными ошибками формы и
  320×568, где несколько экранов прокручиваются); от 600 px тело центрировано шириной 600 px, ответы на S8 — в две/три колонки.
- Матрица S0 (`shot-s0.mjs`): 320×568 … 1440×900 — сцена, размер телефона, виден ли целиком; геометрия рядов S1 (`check-mq.mjs`):
  плитки и бейджи внутри бокса при наклоне.
- Скрипты обхода: `qwalk-lm.mjs`, `dqwalk-lm.mjs` (Playwright) — все ветки, «Назад», правка из подбора, deep-link без состояния.
- Чек-лист `design-system/DESIGN-SYSTEM.md` §11: акцент ≤ 5 % и только в разрешённых местах, радиусы из таблицы §6,
  одна главная кнопка на экран, у полей есть label, у кнопок-иконок — aria-label.

## Что остаётся заглушками

Фахівці, кейсы, населённые пункты, планы Membership и оценки магазинов — фикстуры до подключения данных сайта;
фото фахівців и бегущих рядов — стоковые портреты из `avatarALL`, рейтинги «N/100» в рядах — фикстуры; оплата — имитация
существующего checkout продукта. Экран приложения на S0 — снимок демо, а не живого продукта: при изменении интерфейса пересъёмка через `tools/`.
